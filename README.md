# Cross-Border Order Operations

A Streamlit dashboard for a marketplace seller shipping orders from a US warehouse to customers in Canada through three carrier routes. It answers the three questions an e-commerce operations team asks every day:

1. **Are we keeping our delivery promise, and where is it slipping?** (Overview)
2. **Which orders need someone to act today, and what should they do?** (Exceptions)
3. **Will the coming weeks, including Black Friday, fit our warehouse capacity?** (Forecast & capacity)

> **Synthetic data — demonstration only.** Orders, products and figures are generated by `data/generate_orders.py`.

## Features

**Overview**
- KPIs: on-time delivery vs a 95% target, average and 90th-percentile delivery time, open exceptions, lost parcel rate, shipping cost
- Weekly volume with on-time rate (shown only once a week's orders are at least 90% delivered, so recent weeks don't look artificially good or bad)
- Route trade-off chart: shipping cost vs reliability, sized by volume
- Route × province heatmap that points to the weakest delivery lane
- Plain-language insights calculated from the data (cheapest vs most reliable route, weakest lane, value of likely-lost parcels)

**Exceptions**
- A prioritised work list, not just a report:
  - **P1** likely lost (21+ days, not delivered) → file carrier claim; refund or reship
  - **P2** 5+ days past the promised date → escalate with carrier; send customer a new ETA
  - **P3** 1–4 days past promise → send a proactive delay message
- Sales value at stake per priority and a CSV download of the list

**Forecast & capacity**
- 8-week order forecast with Holt's linear trend method and an 80% range
- Adjustable holiday uplift for Black Friday to mid-December
- Comparison with warehouse prep capacity: weeks *Over* capacity, and weeks *At risk* at the high end of the range

## Run locally

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python data/generate_orders.py     # recreates data/orders.csv (fixed seed)
streamlit run app.py
```

Tests:

```bash
pytest
```

## Methodology

| Rule | Definition |
| --- | --- |
| Delivered | delivery date before the snapshot date (2 Nov 2026) |
| In transit | not delivered, promised date not passed |
| Late | not delivered, promised date passed |
| Likely lost | not delivered, ordered 21+ days ago |
| On time | delivered on or before the promised date (order date + 12 days) |
| Lost parcel rate | likely lost or refunded-lost orders ÷ orders at least 21 days old |

**Forecast.** Holt's linear trend (double exponential smoothing) is fitted on complete weeks only. The smoothing weights are chosen by grid search to minimise one-week-ahead error. The 80% range uses the spread of past one-week-ahead errors and widens with the square root of weeks ahead. The data starts in May, so the model has never seen a holiday season; the peak is therefore an explicit, adjustable assumption rather than something hidden in the model.

## Data dictionary

| Column | Description |
| --- | --- |
| order_id | Synthetic order ID |
| order_date, ship_date | When the order was placed and handed to the carrier |
| promised_date | Delivery date promised at checkout (order date + 12 days) |
| delivered_date | Actual delivery date (empty if not delivered) |
| route | Cross-border carrier → Canadian last-mile carrier |
| province | Destination province |
| category | Product category |
| sale_price_cad | Order value in CAD |
| shipping_cost_usd | Shipping cost per order in USD |
| refunded | True for lost parcels that were already resolved |

## Limitations

Demonstration only: no live marketplace or carrier API connection, no tracking-scan events, and no profit model. In a real deployment, the order and shipment data would come from the marketplace's order reports or API and from carrier tracking feeds.
